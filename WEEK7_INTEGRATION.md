# Week 7 integration setup

This repository shares a Supabase project with `COMS6998-Admin`.

## 1. Turn on email/domain allowlist enforcement

1. Run `sql/allowlist_access.sql` in the Supabase SQL Editor.
2. In the Admin app, add your own approved email to **Whitelisted Email Addresses**, or add an approved domain to **Allowed Signup Domains**. Confirm the entries are marked **Active**.
3. Set `ENFORCE_SIGNUP_ALLOWLIST=true` in the user-facing Vercel project and in local `.env.local`, then redeploy.

Rules: if no active emails or domains are configured, every authenticated user is allowed. Otherwise, matching ANY active email OR active domain grants user-app access. Superadmin authorization remains separate.

The gate is checked after Google OAuth, on the protected dashboard, and on caption generation. Because Google OAuth through Supabase can create an Auth user before our application checks the list, this blocks access rather than preventing creation of the underlying `auth.users` record. To also block direct client Supabase operations, enforce the policy in the database RLS rules on all user-accessible data and Storage buckets (not included here).

## 2. Enable live generation observability

Configure `SUPABASE_SERVICE_ROLE_KEY` in the **user-facing app's server-only environment** (local `.env.local` and its Vercel environment). Never use a `NEXT_PUBLIC_` prefix or disclose this value in client code. Redeploy.

The caption-generation endpoint will then record:
- `generation_requests`: running, completed, or failed requests
- `llm_responses`: the two actual Gemini outputs, token usage where returned, latency
- references to `prompt_chains` and `llm_models` where matching database records already exist

The existing image-upload and caption-generation process remains unchanged, and logging failures don't prevent it from functioning. No new AI image file is generated by this process, so `ai_generated_media` is not written.

## 3. Manual verification

- Sign in with a whitelisted email and confirm access.
- Sign in with an email not on either allowed list and confirm the access-denied page.
- Generate a caption and check Generation Requests and LLM Responses in the admin app.
- Confirm an unauthorized Google user cannot access the protected dashboard or call the caption API.

## 4. Optional real-time AI configuration

After setting `SUPABASE_SERVICE_ROLE_KEY` and registering your genuine prompt chain:
1. Create an active **Google** or **Gemini** provider in the admin app and active Gemini model records. Their `model_identifier` must be an actual Google Gemini model ID.
2. Set `USE_DB_AI_CONFIGURATION=true` in the user-facing app's server-side environment and redeploy.
3. The caption endpoint will attempt active configured Gemini model identifiers first, falling back to its existing hardcoded model list on model API failures.
4. The caption endpoint will select from active, positively weighted prompt chains. Currently, only chains with exactly two ordered steps are executable by this application. Step 1 receives the image; Step 2 can reference `{description}` to insert Step 1's output. If no compatible chain is configured, the existing hardcoded prompts remain in use.
5. Changing prompt-chain weights affects relative selection only when multiple compatible chains exist. A single chain with any positive weight is always selected.

**Important:** The configuration integration is opt-in and must be built/tested before relying on it in production. `terms` and `ai_generation_examples` remain data-management features because the Week 7 rubric does not define runtime semantics for them.
